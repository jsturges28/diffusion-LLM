    LLM Visualizer

    This tool visualizes discrete diffusion language modeling in real time. Instead of generating text one token at a time (left to right), a diffusion LLM starts from noise or masked tokens and iteratively refines an entire block over many denoising steps. The playground also hosts a compact autoregressive (left-to-right) model as a baseline for contrast. Use the Model selector in the header to switch between the available models (only one is resident in GPU memory at a time).

    How diffusion LLMs work

    The forward process corrupts text by independently replacing each token with a placeholder at a rate controlled by a noise schedule. The reverse process starts from a corrupted canvas and uses a Transformer with bidirectional attention to predict all positions simultaneously, then re-noises (re-masks) the least confident predictions. This repeats for N steps until the sequence converges. Unresolved positions are shown as ░ until they stabilize.

    Models

    LLaDA-8B-Instruct: the first competitive large-scale discrete diffusion language model, pre-trained on 2.3T tokens and instruction-tuned, comparable to LLaMA 3 8B. It performs masked diffusion over a single canvas with optional semi-autoregressive blocks, runs in bf16 (~17 GB VRAM), and supports interactive remasking / resume.

    DiffusionGemma-26B-A4B: Google's block-autoregressive text-diffusion model, a 26B-parameter Mixture-of-Experts (~4B active) built on Gemma 4, run here as a self-quantized 4-bit NF4 checkpoint (~18 GB VRAM). It denoises 256-token canvases with an entropy-bounded sampler and adaptive stopping (variable step count), chains canvases for longer outputs, and exposes an optional step-by-step reasoning (thinking) channel.

    SmolLM3-3B: a compact 3B-parameter autoregressive (left-to-right) decoder-only transformer, included as a baseline for contrast with the diffusion models. It streams tokens one at a time with per-token sampling confidence, runs in bf16 on GPU or CPU (selectable per activation, so GPU-less hosts can still use it), and exposes an optional reasoning (thinking) channel. Because it generates strictly left to right, it has no interactive remasking / Edit Frames; it carries its own explainability tools instead: per-token entropy, an optional top-5 Alternatives capture, and What If? substitution.

    Help

    Quick start

    1. On the Main Menu, pick a model. Rows that will not fit in the available GPU memory are greyed out. Selecting one loads it and opens this generator (the generator is reachable only after a model is chosen).
    2. Wait for the model to load (the overlay dismisses automatically). To switch models later, use the Model selector in the header; it unloads the current model and loads the other, since only one fits in GPU memory at a time.
    3. Type a prompt in the text area.
    4. Adjust hyperparameters if desired, then click Generate.
    5. Watch the canvas resolve into text in real time; unresolved positions appear as ░.
    6. While the model runs, Generate is disabled and the status bar shows an animated Running… until the run completes.

    The Main Menu model list is paginated: use the ‹ i/N › arrows to browse it. If a model's weights are not cached yet, its row shows Click to Download, which fetches them (with a progress bar, no GPU needed) before the model can be selected. You can navigate freely (menu pages, Analytics, Settings) while a download runs; a small draggable download toast tracks its progress from any page and returns you to the menu when you click it. An interrupted download resumes where it left off the next time you click.

    Header links move between pages: Menu returns to model selection, and Analytics opens the analytics suite. From Analytics, a Generation link appears whenever a model is loaded. A gear icon in the header opens the shared Settings page.

    Models

    LLaDA-8B-Instruct
    Masked diffusion over a single canvas with optional semi-autoregressive blocks. Supports interactive remasking / resume.
    DiffusionGemma-26B-A4B (NF4)
    Block-autoregressive diffusion over 256-token canvases with adaptive stopping and an optional reasoning channel. Because it denoises canvas-by-canvas with a variable step count, its status readout reads Step X, Canvas Y (the current step and which canvas it belongs to) rather than a fixed step total. Single-canvas runs support interactive remasking / resume (via seed-canvas re-entry); multi-canvas runs do not yet, so Edit Frames is disabled for them.
    SmolLM3-3B (autoregressive)
    A compact decoder-only transformer that generates left to right, streamed token-by-token with per-token sampling confidence. It runs on GPU or CPU (selectable per activation, so GPU-less hosts can still use it). Because generation is inherently left-to-right, it has no interactive remasking, so Edit Frames and Commit Order do not apply. It has its own explainability tools instead: per-token entropy (an Entropy overlay plus an entropy profile under the scrubber), an optional Alternatives capture shown on hover, and What If? substitution, which also makes Diff vs Original available. Its step counter is 1-based, so a full N-token run reads Step N/N.

    Hyperparameters

    LLaDA

    Steps
    How many denoising iterations run to turn a fully masked canvas into finished text. Each step unmasks a batch of the most confident tokens, so more steps let the model commit more gradually; this usually raises quality but is proportionally slower.
    Gen Length
    The size of the canvas: how many tokens the output can hold. The whole canvas exists from step 0 (as mask tokens) and is filled in place. Must be divisible by Block Length.
    Block Length
    Splits the canvas into left-to-right blocks that are diffused one after another (semi-autoregressive). Smaller blocks trade some parallelism for more left-to-right coherence; setting it equal to Gen Length gives pure, fully-parallel diffusion over the whole canvas.
    Temperature
    Controls randomness when sampling each token (via Gumbel noise). 0 is greedy/deterministic (always the argmax); higher values add diversity at the cost of stability.
    CFG Scale
    Classifier-free guidance strength. 0 disables it; higher values push the output to follow the prompt more closely by amplifying the gap between prompt-conditioned and unconditioned predictions.
    Seed
    Fixes the random number generator so a run is reproducible. Use −1 for a fresh, nondeterministic run each time.
    Remasking
    Which tokens get re-masked between steps. Low Confidence keeps the most confident predictions and re-masks the rest (the principled default); Random re-masks arbitrarily, mostly useful for experimentation.

    DiffusionGemma

    Max Tokens
    The output budget. DiffusionGemma generates in fixed 256-token canvases; when this exceeds 256 it chains multiple canvases block-autoregressively, committing one before starting the next.
    Denoising Steps
    The upper bound on denoising iterations per canvas. Thanks to adaptive stopping, a canvas often finishes early, once its predictions stop changing and the model is confident, so simpler prompts run faster than complex ones.
    Temp Start / Temp End
    Endpoints of a linear temperature schedule across the denoising steps. Starting hotter and cooling down lets the model explore broadly early, then sharpen toward a confident answer as the canvas converges.
    Seed
    Fixes the random number generator so a run is reproducible. Use −1 for a fresh, nondeterministic run each time.
    Thinking
    Enables a step-by-step reasoning pass before the answer. When on, the model's private reasoning is separated into a collapsible Reasoning panel above the output, keeping the final answer clean.
    Entropy signal
    Changes how per-token confidence is measured. Off (default), confidence is a fast stability proxy. On, it is the model's true certainty computed from the full output distribution (the max-softmax probability) at each step: more faithful, but slower and heavier, so enable it only when you specifically want to study confidence.

    SmolLM3 (autoregressive)

    Max Tokens
    How many tokens to generate. Because each saved frame is a full snapshot, the stream payload grows with the token count, so the recommended ceiling stays modest (and is lower on CPU, where decoding is slower).
    Temperature
    Controls randomness when sampling each token. 0 is greedy/deterministic (always the argmax); higher values add diversity at the cost of stability.
    Top-p
    Nucleus sampling: restrict each choice to the smallest set of most-likely tokens whose probabilities sum to p. Lower values keep only the very likeliest tokens (safer, less diverse); 1.0 disables the cutoff.
    Seed
    Fixes the random number generator so a run is reproducible. Use −1 for a fresh, nondeterministic run each time.
    Thinking
    Enables an extended step-by-step reasoning pass before the answer. When on, the model's reasoning is separated into a collapsible Reasoning panel above the output, keeping the final answer clean.
    Alternatives
    Captures the five most likely tokens at every position, not just the one that was chosen. Hovering a token then shows what the model nearly said instead, and it is required for What If? substitution. Costs a little extra time per token, so it is off by default.

    Confidence & the heatmap

    Every resolved token carries a confidence value in [0, 1], and each frame carries the mean confidence of its resolved tokens. What confidence means depends on the model:

    LLaDA
    The softmax probability of the token at the moment it was unmasked. It is recorded once and stays fixed for the rest of the run, since resolved tokens are never revisited.
    DiffusionGemma
    By default a lightweight stability proxy: how many consecutive steps a position has held the same prediction (so a freshly settled token starts low and climbs as it stays put). Enable Entropy signal to instead use the true max-softmax probability from the model's logits.
    SmolLM3
    The softmax probability of the chosen token at the moment it was generated. Like LLaDA, it is recorded once and stays fixed, since autoregressive tokens are never revisited.

    After a run, hover any token in the output to read its confidence for the current frame; masked / unresolved tokens report 0. Select Heatmap in the Overlay drawer (top-right of the output area) to recolor resolved tokens by confidence: dim, desaturated tones mark low-confidence tokens and bright green marks high-confidence ones. The heatmap is a live view over the frame you are viewing and is not saved. See Visual overlays & settings below for the other overlays.

    Entropy & alternatives

    Confidence answers "how likely was the token it picked?". Entropy answers a different question: "how spread out was the model's whole distribution?". A token can be picked with modest confidence from two close rivals (low entropy, a real coin-flip between two options) or from thousands of vaguely plausible options (high entropy, genuinely unsure). Entropy is reported in nats: 0 means complete certainty, and about 5 nats is roughly an even choice among 150 tokens, which is about as torn as a language model gets.

    Autoregressive runs always capture it. Hovering a token adds an Entropy line to its tooltip, the Entropy overlay recolors tokens from cool blue (decisive) to hot amber (torn), and an entropy profile appears below the scrubber: one column per position, tall and hot where the model hesitated, with the column for your current frame highlighted. Hovering a token makes its column glow and shows that position's value, in nats, at the right of the profile. Because an autoregressive model decides each position exactly once, that profile reads across the sequence rather than over time.

    The profile and the text cross-highlight, so you can read in either direction: hover a token to light its column, or sweep the profile to light the token behind any column that catches your eye. That one is always on, separate from the Highlight tokens setting, because it is a way of reading the run rather than a comfort preference.

    Turn on the Alternatives hyperparameter before generating to also capture the top five candidates at each position. Hovering a token then opens a popover listing them with a probability bar each, and the one the model actually chose is highlighted. Whitespace and control tokens are shown with visible stand-ins (· for a space, ↵ for a newline) so an invisible candidate is still legible.

    What If? (autoregressive counterfactuals)

    Because a left-to-right model cannot be remasked, it gets a different intervention. After a SmolLM3 run generated with Alternatives on, a What If? button appears beside the scrubber.

    1. Click What If?. Positions that captured candidates pick up a dotted underline.
    2. Hover one to open its candidate popover, then click a candidate to force it.
    3. The model regenerates everything after that position, and you land in the same Confirm / Retry review as a diffusion edit.

    There is no frame-selection step here: for a left-to-right model the frame and the position are the same choice. The continuation is decoded greedily, so what changes downstream is the effect of your intervention rather than fresh sampling noise. Only a token the model genuinely weighed at that position can be forced, which keeps the result a real counterfactual rather than an arbitrary edit. Entry auto-saves the original run, and once the branch is confirmed, Diff vs Original becomes available to compare the two.

    After a branch exists, the candidate popover gains a small ‹ › pager at positions from the substitution onward, flipping between what the Original run and the Edited branch were weighing at the same position. Each page marks the token its own run drew. Positions before the substitution have no pager, because a branch reproduces its prefix exactly, candidates included. Only the Edited page is clickable while What If? is armed: the original run is a record, not something you can substitute into.

    Interactive remasking & resume

    After a generation completes, a frame scrubber appears below the output area for any model. Use the slider or ‹ › buttons to explore frames. Press Left / Right arrow keys or Home / End to navigate. The remasking / resume tools below work for LLaDA and for single-canvas DiffusionGemma runs; they are unavailable for autoregressive runs (SmolLM3, which generates left-to-right) and on multi-canvas DiffusionGemma runs, where Edit Frames is disabled.

    Guided multi-frame editing

    Click the Edit Frames button to enter the guided editing flow:

    1. Select a frame: Navigate to the frame you want to edit and click Select Frame. The scrubber starts at frame 0 and only allows forward navigation.
    2. Remask tokens: Click resolved tokens to remask them (they turn orange). Click again to deselect. When ready, click 🔒 Lock In. For LLaDA the tokens are set back to [MASK]; for DiffusionGemma they are renoised, so committed neighbours may also shift on resume.
    3. Choose next action:
      • Edit Another Frame: enters target selection mode. Navigate to a later frame you want to edit next; a faded preview of the original run is shown at each frame as a reference, with a note that the output will diverge based on your edits. Click Run to Here to resume the model up to that frame. You are then placed directly into edit mode on the target frame.
      • Resume to End: resumes the model from your last edit through all remaining steps to produce the final output.

    A single edit followed by Resume to End is the simplest case; you can also chain as many frame edits as you like. Each partial resume generates only the frames between your last edit and your next target, so earlier edits propagate forward through every subsequent segment. The scrubber enforces forward-only navigation; later edits cannot precede earlier ones.

    Click Exit at any time to leave guided editing; this discards any in-progress edits and restores the original run. All remask edits (frame indices and token positions) are recorded automatically and included in saved results.

    Visual overlays & settings

    A collapsible Overlay drawer in the top-right of the output area recolors the frame you are viewing. It defaults to None:

    • Heatmap: recolor resolved tokens by confidence (see Confidence & the heatmap above).
    • Entropy: recolor resolved tokens from cool blue (decisive) to hot amber (torn), by how spread the model's distribution was (see Entropy & alternatives above). Listed for runs that carry the signal, which today means autoregressive runs.
    • Commit Order: tint resolved tokens by the step at which they settled, from light green (early) to red-orange (late), with a matching gradient legend in the status bar. Diffusion runs only.
    • Diff vs Original: compare an edited run against the original. Diffusion runs list it up front, disabled until you have edited and resumed a run; autoregressive runs list it once a What If? substitution has produced a branch. When active, a slim row below the scrubber adds independent Original / Edited opacity sliders and a Difference blend toggle (matching tokens cancel to black, divergences glow), plus a Diverged N/total readout.

    Preferences live on a shared Settings page, opened from the gear icon in the header (the Main Menu and Analytics have the same gear). Changes are staged behind Save / Reset, saved on the server, and shared across every page:

    • Render diffusion-style text: dynamic status messages resolve from scrambled block-glyph noise, like a denoising pass; a Mode sub-setting picks Default (resolve once) or Cycle (keep re-diffusing while the status is active). Skipped automatically under reduced-motion.
    • Highlight tokens: add a light hover highlight so the full span of the hovered token is easy to see.
    • Device tag ticker: the scrolling GPU / device readout on the model tag.

    The status bar reflects the highlight toggle (Highlighted Tokens: On/Off). Hovering any token shows its position and confidence for the current frame.

    Analytics Suite

    Click Analytics in the header to open the Analytics Suite. It reads saved runs from the results/ directory and provides interactive charts for comparing generation behavior across configurations.

    Run browser

    Runs can be grouped by model, prompt, or any hyperparameter using the Group by dropdown (default: Date, i.e. ungrouped and sorted newest-first). Select a run to view its details, including the model, prompt, hyperparameters, timestamp, and final output. The table shows columns shared across models; model-specific hyperparameters stay in the detail panel. To remove a run, click its trashcan action: a confirmation modal shows the run's folder path (results/<timestamp>_<model>) and a toast confirms the deletion.

    Token overlay

    The detail modal centers a token view of the run with its own Overlay drawer (top-right) and a frame scrubber that replays every saved frame, mirroring the generator (it opens on the final frame). The overlays are None, Heatmap (recolor resolved tokens by persisted confidence), Entropy (for runs saved with the signal), Commit Order (tint by the step each token settled on), and Diff vs Original (for edited runs saved with their pre-edit snapshot: stacks the original and edited runs with independent Original / Edited opacity sliders, a Difference blend toggle, and a Diverged N/total readout). Commit Order applies to diffusion runs only; Diff appears for any edited run, including an autoregressive What If? branch. Runs saved with captured candidates also get the generator's hover popover, so a decision and the branch taken from it stay inspectable long after the run. Runs saved before durable overlays (or without token data) show a short unavailable note.

    For an edited run saved with its pre-edit snapshot, an Original / Edited crossfade sits at the right of the Token overlay heading row, above the text it blends. It governs the whole modal at once: the token view stacks both runs and blends between them in any overlay, and the entropy chart's bars follow the same slider. Each layer is colored by its own run's values, so at full Original the Heatmap shows the original run's confidence rather than the branch's colors under the original text. Whichever side is more opaque takes the pointer, so hovering, the candidate popover, and cross-highlighting always read the run you are looking at. Diff vs Original is the exception: it keeps its own two sliders, because the Difference blend needs both layers up at once.

    Convergence chart

    Plots the percentage of resolved (unmasked) tokens at each frame. The curve shows how quickly the model commits to its output. If the run includes user remask edits, the transition segments leading into edited frames are highlighted in blue, and hovering reveals which token positions were remasked.

    Timing chart

    Plots cumulative elapsed time per frame. Time accumulates across resume operations so the chart shows total wall-clock cost, and the Elapsed figure in the run summary reports that same total (for an edited run, the original plus the branch, not the branch alone). Transition segments into remasked frames are highlighted in green, and the resumed stretch after an edit is drawn in a lighter blue. The detected GPU is displayed in the chart header.

    Confidence chart

    Plots the mean per-token confidence at each frame, which typically climbs toward 100% as a canvas converges. This makes DiffusionGemma's adaptive stopping visible: confidence rises and then a canvas commits. Shown only for runs saved with confidence data.

    Entropy chart

    The one chart indexed by token position rather than by frame, which is why it is drawn as bars: an autoregressive model decides each position exactly once, so its entropy is a property of the position, not a point in a time series. One bar per generated token, colored on the same cool-blue to hot-amber ramp as the Entropy overlay, so tall warm bars mark the moments the model was torn. Hovering lights the column and names the token at that position alongside its value in nats, the same highlight the generator's entropy profile uses, and it also lights the matching token in the overlay above. That works in reverse too: hovering a token lights its bar. Shown for runs saved with the entropy signal, which today means autoregressive runs.

    If the run carries edits, a dashed orange marker and a faint tint of the same color sit on each edited position, matching the color the generator uses for remasks and substitutions. From that position rightward the tooltip splits into two rows, Original and Edited, since that is where a What If? branch stops sharing its prefix and the two runs become worth comparing. At the marked position itself both rows show the same nats and different tokens: entropy describes the distribution the prefix produced, and forcing a token changes which one was drawn, not the distribution it was drawn from.

    For edited runs saved with their pre-edit snapshot, the Original / Edited crossfade above the token view blends this chart's two bar layers along with the text. Left shows the original run's bars at full opacity, right the branch's, and anywhere between blends the two. Because the branch copies its prefix verbatim, the crossfade only visibly moves to the right of the marker, which is itself a reading of how far the intervention reached.

    Canvas boundaries

    For multi-canvas DiffusionGemma runs, dashed amber markers on the convergence, timing, and confidence charts mark the frames where one canvas commits and the next begins. Single-canvas runs (including all LLaDA runs) show no markers.

    Chart controls

    Every chart supports scroll-wheel zoom and + / − / Reset buttons for zooming and resetting the view. Tooltip boxes park in whichever corner of the plot area is free of both the data and the pointer, preferring top-left and falling back through top-right, bottom-left, and bottom-right, and they stay fully inside the plot area rather than spilling onto the axes. Each chart has an eye toggle to hide/show its box. When every corner is occupied and the box has nowhere clear to go, the covered segment and the hovered point glow through it.

    Saving results

    The Save button (the down-arrow icon to the left of Generate) becomes enabled once a run completes. Clicking it saves the run to a timestamped folder under results/ containing:

    • metadata.json: prompt, hyperparameters, final output text, reproducibility info, and any remask edits.
    • final.txt: the decoded final text.
    • history.txt: frame-by-frame snapshots of the diffusion process.
    • tokens.json: per-frame token records (text, mask flag, vocab id, confidence, and entropy where captured) that drive the durable overlays in Analytics.
    • alternatives.json: the captured top-five candidates per position, written only for runs generated with Alternatives on.
    • diffusion.gif: an animated GIF visualizing the denoising progression.

    It is disabled during generation and after a successful save (to prevent duplicates); while saving it shows a spinner, then a brief checkmark. Starting a new generation resets it.

    Experimental mode

    The toggle above the parameter controls removes the recommended bounds, allowing extreme values for exploratory purposes. The default bounds represent the range that produces more consistent, stable results.
