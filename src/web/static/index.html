    Diffusion LLM Visualizer

    This tool visualizes discrete diffusion language modeling in real time. Instead of generating text one token at a time (left to right), a diffusion LLM starts from noise or masked tokens and iteratively refines an entire block over many denoising steps. Use the Model selector in the header to switch between the available models (only one is resident in GPU memory at a time).

    How diffusion LLMs work

    The forward process corrupts text by independently replacing each token with a placeholder at a rate controlled by a noise schedule. The reverse process starts from a corrupted canvas and uses a Transformer with bidirectional attention to predict all positions simultaneously, then re-noises (re-masks) the least confident predictions. This repeats for N steps until the sequence converges. Unresolved positions are shown as ░ until they stabilize.

    Models

    LLaDA-8B-Instruct: the first competitive large-scale discrete diffusion language model, pre-trained on 2.3T tokens and instruction-tuned, comparable to LLaMA 3 8B. It performs masked diffusion over a single canvas with optional semi-autoregressive blocks, runs in bf16 (~17 GB VRAM), and supports interactive remasking / resume.

    DiffusionGemma-26B-A4B: Google's block-autoregressive text-diffusion model, a 26B-parameter Mixture-of-Experts (~4B active) built on Gemma 4, run here as a self-quantized 4-bit NF4 checkpoint (~18 GB VRAM). It denoises 256-token canvases with an entropy-bounded sampler and adaptive stopping (variable step count), chains canvases for longer outputs, and exposes an optional step-by-step reasoning (thinking) channel.

    Help

    Quick start

    1. On the Main Menu, pick a model. Rows that will not fit in the available GPU memory are greyed out. Selecting one loads it and opens this generator (the generator is reachable only after a model is chosen).
    2. Wait for the model to load (the overlay dismisses automatically). To switch models later, use the Model selector in the header; it unloads the current model and loads the other, since only one fits in GPU memory at a time.
    3. Type a prompt in the text area.
    4. Adjust hyperparameters if desired, then click Generate.
    5. Watch the canvas resolve into text in real time; unresolved positions appear as ░.
    6. While the model runs, Generate is disabled and the status bar shows an animated Running… until the run completes.

    Header links move between pages: Menu returns to model selection, and Analytics opens the analytics suite. From Analytics, a Generation link appears whenever a model is loaded.

    Models

    LLaDA-8B-Instruct
    Masked diffusion over a single canvas with optional semi-autoregressive blocks. Supports interactive remasking / resume.
    DiffusionGemma-26B-A4B (NF4)
    Block-autoregressive diffusion over 256-token canvases with adaptive stopping and an optional reasoning channel. Because it denoises canvas-by-canvas with a variable step count, its status readout reads Step X, Canvas Y (the current step and which canvas it belongs to) rather than a fixed step total. Single-canvas runs support interactive remasking / resume (via seed-canvas re-entry); multi-canvas runs do not yet, so Edit Frames is disabled for them.

    Hyperparameters

    LLaDA

    Steps
    How many denoising iterations run to turn a fully masked canvas into finished text. Each step unmasks a batch of the most confident tokens, so more steps let the model commit more gradually; this usually raises quality but is proportionally slower.
    Gen Length
    The size of the canvas: how many tokens the output can hold. The whole canvas exists from step 0 (as mask tokens) and is filled in place. Must be divisible by Block Length.
    Block Length
    Splits the canvas into left-to-right blocks that are diffused one after another (semi-autoregressive). Smaller blocks trade some parallelism for more left-to-right coherence; setting it equal to Gen Length gives pure, fully-parallel diffusion over the whole canvas.
    Temperature
    Controls randomness when sampling each token (via Gumbel noise). 0 is greedy/deterministic (always the argmax); higher values add diversity at the cost of stability.
    CFG Scale
    Classifier-free guidance strength. 0 disables it; higher values push the output to follow the prompt more closely by amplifying the gap between prompt-conditioned and unconditioned predictions.
    Seed
    Fixes the random number generator so a run is reproducible. Use −1 for a fresh, nondeterministic run each time.
    Remasking
    Which tokens get re-masked between steps. Low Confidence keeps the most confident predictions and re-masks the rest (the principled default); Random re-masks arbitrarily, mostly useful for experimentation.

    DiffusionGemma

    Max Tokens
    The output budget. DiffusionGemma generates in fixed 256-token canvases; when this exceeds 256 it chains multiple canvases block-autoregressively, committing one before starting the next.
    Denoising Steps
    The upper bound on denoising iterations per canvas. Thanks to adaptive stopping, a canvas often finishes early, once its predictions stop changing and the model is confident, so simpler prompts run faster than complex ones.
    Temp Start / Temp End
    Endpoints of a linear temperature schedule across the denoising steps. Starting hotter and cooling down lets the model explore broadly early, then sharpen toward a confident answer as the canvas converges.
    Seed
    Fixes the random number generator so a run is reproducible. Use −1 for a fresh, nondeterministic run each time.
    Thinking
    Enables a step-by-step reasoning pass before the answer. When on, the model's private reasoning is separated into a collapsible Reasoning panel above the output, keeping the final answer clean.
    Entropy signal
    Changes how per-token confidence is measured. Off (default), confidence is a fast stability proxy. On, it is the model's true certainty computed from the full output distribution (the max-softmax probability) at each step: more faithful, but slower and heavier, so enable it only when you specifically want to study confidence.

    Confidence & the heatmap

    Every resolved token carries a confidence value in [0, 1], and each frame carries the mean confidence of its resolved tokens. What confidence means depends on the model:

    LLaDA
    The softmax probability of the token at the moment it was unmasked. It is recorded once and stays fixed for the rest of the run, since resolved tokens are never revisited.
    DiffusionGemma
    By default a lightweight stability proxy: how many consecutive steps a position has held the same prediction (so a freshly settled token starts low and climbs as it stays put). Enable Entropy signal to instead use the true max-softmax probability from the model's logits.

    After a run, hover any token in the output to read its confidence for the current frame; masked / unresolved tokens report 0. Select Heatmap in the Overlay drawer (top-right of the output area) to recolor resolved tokens by confidence: dim, desaturated tones mark low-confidence tokens and bright green marks high-confidence ones. The heatmap is a live view over the frame you are viewing and is not saved. See Visual overlays & settings below for the other overlays.

    Interactive remasking & resume

    After a generation completes, a frame scrubber appears below the output area for any model. Use the slider or ‹ › buttons to explore frames. Press Left / Right arrow keys or Home / End to navigate. The remasking / resume tools below work for LLaDA and for single-canvas DiffusionGemma runs; on multi-canvas DiffusionGemma runs Edit Frames is disabled.

    Guided multi-frame editing

    Click the Edit Frames button to enter the guided editing flow:

    1. Select a frame: Navigate to the frame you want to edit and click Select Frame. The scrubber starts at frame 0 and only allows forward navigation.
    2. Remask tokens: Click resolved tokens to remask them (they turn orange). Click again to deselect. When ready, click 🔒 Lock In. For LLaDA the tokens are set back to [MASK]; for DiffusionGemma they are renoised, so committed neighbours may also shift on resume.
    3. Choose next action:
      • Edit Another Frame: enters target selection mode. Navigate to a later frame you want to edit next; a faded preview of the original run is shown at each frame as a reference, with a note that the output will diverge based on your edits. Click Run to Here to resume the model up to that frame. You are then placed directly into edit mode on the target frame.
      • Resume to End: resumes the model from your last edit through all remaining steps to produce the final output.

    A single edit followed by Resume to End is the simplest case; you can also chain as many frame edits as you like. Each partial resume generates only the frames between your last edit and your next target, so earlier edits propagate forward through every subsequent segment. The scrubber enforces forward-only navigation; later edits cannot precede earlier ones.

    Click Exit at any time to leave guided editing; this discards any in-progress edits and restores the original run. All remask edits (frame indices and token positions) are recorded automatically and included in saved results.

    Visual overlays & settings

    A collapsible Overlay drawer in the top-right of the output area recolors the frame you are viewing. It defaults to None:

    • Heatmap: recolor resolved tokens by confidence (see Confidence & the heatmap above).
    • Diff vs Original: compare an edited run against the original. It stays listed but disabled until you have edited and resumed a run. When active, a slim row below the scrubber adds independent Original / Edited opacity sliders and a Difference blend toggle (matching tokens cancel to black, divergences glow), plus a Diverged N/total readout.

    Two preferences live in Settings (in the header) and persist per-browser; the modal stages changes behind Save / Reset with inline status feedback:

    • Show Commit Order: tint resolved tokens by the step at which they settled, from light green (early) to red-orange (late), with a matching gradient legend in the status bar.
    • Highlight tokens: add a light hover highlight so the full span of the hovered token is easy to see.

    The status bar shows both (Highlighted Tokens: On/Off, Show Commit Order: On/Off). An explicit overlay selection (Heatmap or Diff) takes precedence; otherwise Commit Order, when enabled, is the ambient tint.

    Analytics Suite

    Click Analytics in the header to open the Analytics Suite. It reads saved runs from the Results/ directory and provides interactive charts for comparing generation behavior across configurations.

    Run browser

    Runs can be grouped by model, prompt, or any hyperparameter using the Group by dropdown (default: Date, i.e. ungrouped and sorted newest-first). Select a run to view its details, including the model, prompt, hyperparameters, timestamp, and final output. The table shows columns shared across models; model-specific hyperparameters stay in the detail panel. To remove a run, click its trashcan action: a confirmation modal shows the run's folder path (Results/<timestamp>_<model>) and a toast confirms the deletion.

    Token overlay

    The detail modal centers a static token view of the run's final frame with its own Overlay drawer (top-right), mirroring the generator. Commit Order tints tokens by the step they settled on, and Diff vs Original (available for edited runs saved with their pre-edit snapshot) stacks the original and edited runs with independent Original / Edited opacity sliders and a Difference blend toggle, plus a Diverged N/total readout. Runs saved before durable overlays (or without token data) show a short unavailable note.

    Convergence chart

    Plots the percentage of resolved (unmasked) tokens at each frame. The curve shows how quickly the model commits to its output. If the run includes user remask edits, the transition segments leading into edited frames are highlighted in blue, and hovering reveals which token positions were remasked.

    Timing chart

    Plots cumulative elapsed time per frame. Time accumulates across resume operations so the chart shows total wall-clock cost. Transition segments into remasked frames are highlighted in green. The detected GPU is displayed in the chart header.

    Confidence chart

    Plots the mean per-token confidence at each frame, which typically climbs toward 100% as a canvas converges. This makes DiffusionGemma's adaptive stopping visible: confidence rises and then a canvas commits. Shown only for runs saved with confidence data.

    Canvas boundaries

    For multi-canvas DiffusionGemma runs, dashed amber markers on the convergence, timing, and confidence charts mark the frames where one canvas commits and the next begins. Single-canvas runs (including all LLaDA runs) show no markers.

    Chart controls

    Every chart supports scroll-wheel zoom and + / − / Reset buttons for zooming and resetting the view. Tooltips are kept fully inside the plot area (never spilling onto the axes), and each chart has an eye toggle to hide/show its tooltip box; when the box would cover a line, the covered segment and the hovered point glow through it.

    Saving results

    The Save button (the down-arrow icon to the left of Generate) becomes enabled once a run completes. Clicking it saves the run to a timestamped folder under Results/ containing:

    • metadata.json: prompt, hyperparameters, final output text, reproducibility info, and any remask edits.
    • final.txt: the decoded final text.
    • history.txt: frame-by-frame snapshots of the diffusion process.
    • diffusion.gif: an animated GIF visualizing the denoising progression.

    It is disabled during generation and after a successful save (to prevent duplicates); while saving it shows a spinner, then a brief checkmark. Starting a new generation resets it.

    Experimental mode

    The toggle above the parameter controls removes the recommended bounds, allowing extreme values for exploratory purposes. The default bounds represent the range that produces more consistent, stable results.
